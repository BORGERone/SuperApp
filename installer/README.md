# SuperApp — развёртывание на Windows

Инструментарий для установки **сервера** (Windows 10) и **клиента**
(Windows 10/11, а также Windows 7) не на `localhost`, а на отдельном сервере,
с интерактивной настройкой и генерацией секретов.

> Поддержка только Windows. Сервер требует [Bun](https://bun.sh) (Windows 10+).
> Клиенты на Windows 7 ставятся готовым `.exe` (см. ниже) — Bun на них не нужен.

## Файлы

| Файл                                  | Где запускать                | Что делает                                                        |
|---------------------------------------|------------------------------|-------------------------------------------------------------------|
| `build-client.bat` (корень репозитория) | на сборочной машине Win10/11 | Собирает распространяемый установщик клиента `.exe` (NSIS). Можно «запечь» адрес сервера |
| `installer\setup-server.bat`          | на сервере (Win10)           | Полная интерактивная установка сервера: `bun install`, порт, ключи, `.env` |
| `installer\setup-client.bat`          | на машине-клиенте (Win10/11) | Полная интерактивная настройка клиента из исходников: `bun install`, адрес сервера (`config.json`), сборка веб-бандла |
| `installer\configure-server.bat`      | на сервере                   | Быстро (пере)записать только `.env` (порт/HOST/CORS/секрет)        |
| `installer\configure-client.bat`      | на машине-клиенте            | Быстро (пере)записать только `config.json` (IP/порт сервера)       |

`installer\install-server.ps1` и `installer\install-client.ps1` — это «движок»
(проверка Bun, `bun install`, сборка, генерация секрета), который вызывают `.bat`.
Их можно запускать и напрямую из PowerShell, например:
`powershell -ExecutionPolicy Bypass -File installer\install-client.ps1 -Package`.

## Установка СЕРВЕРА (Windows 10)

Вариант А — прямо в каталоге проекта на сервере:
1. Установите Bun: `powershell -c "irm bun.sh/install.ps1 | iex"`.
2. Двойной клик по **`installer\setup-server.bat`**.
3. Ответьте на вопросы (порт, HOST, CORS). `JWT_SECRET` сгенерируется сам.
4. Запуск: `cd packages\server` и `bun run src\server.ts`.

Вариант Б — перенос папкой:
1. Скопируйте каталог проекта на сервер (можно без `node_modules` — `setup-server.bat`
   сам выполнит `bun install`).
2. На сервере: установите Bun и запустите **`installer\setup-server.bat`**.

Чтобы только перегенерировать `.env` без переустановки зависимостей — двойной клик
по **`installer\configure-server.bat`**.

Запуск как службы Windows (рекомендуется [NSSM](https://nssm.cc)):
```
nssm install SuperAppServer "C:\Users\<user>\.bun\bin\bun.exe" "run src\server.ts"
nssm set SuperAppServer AppDirectory "C:\path\to\packages\server"
nssm start SuperAppServer
```

## Установка КЛИЕНТА

### Win10/11 — настроить клиент из исходников
Если клиент запускается из этого же репозитория (есть Bun), проще всего:
1. Установите Bun: `powershell -c "irm bun.sh/install.ps1 | iex"`.
2. Двойной клик по **`installer\setup-client.bat`**.
3. Укажите протокол (`http`/`https`), IP/домен и порт сервера. Будет записан
   `config.json` и собран веб-бандл (`bun run build`).
   - `setup-client.bat /nobuild` — только перезаписать `config.json` без сборки;
   - `setup-client.bat /defaults` — без вопросов (значения по умолчанию/из текущего `config.json`).

### Win10/11 — собрать установщик .exe
1. На сборочной машине (Win10/11) двойной клик по **`build-client.bat`** (в корне репозитория).
2. Введите адрес сервера (например `http://192.168.1.10:3002`), чтобы «запечь»
   его в сборку — тогда клиенты заработают сразу, без доп. настройки. Либо
   оставьте пустым и задавайте адрес на каждой машине отдельно (см. ниже).
3. Готовый установщик: `packages\client\dist-electron\SuperApp Setup *.exe`.
4. Распространите `.exe`, пользователи устанавливают обычным способом.

### Windows 7 — пара устройств
Bun на Win7 не работает, поэтому **собирать на Win7 нельзя**. Соберите `.exe` на
Win10/11 (шаги выше) и установите его на Win7 — Electron 22 поддерживает Win7.
Адрес сервера на Win7 задаётся одним из способов:
- **проще всего:** при сборке указать адрес (он «запекается» в `.exe`);
- либо положить файл `config.json` рядом с установленным `SuperApp.exe`:
  ```json
  { "apiBaseUrl": "http://192.168.1.10:3002" }
  ```
- либо задать переменную окружения `SUPERAPP_API_URL`.

### Изменить адрес сервера у уже установленного клиента
Отредактируйте `config.json` рядом с `SuperApp.exe` (или в каталоге данных
приложения `%APPDATA%\SuperApp\config.json`) вручную, либо запустите
**`installer\configure-client.bat`** для интерактивной перезаписи. Перезапустите приложение.

Порядок поиска адреса сервера клиентом (главный процесс Electron):
1. `SUPERAPP_API_URL` (или `SUPERAPP_CONFIG` — путь к json);
2. `config.json` рядом с `.exe`;
3. `config.json` в `%APPDATA%\SuperApp`;
4. адрес, «запечённый» при сборке (`VITE_API_URL`);
5. фолбэк `http://localhost:3002` (для локальной разработки).

## Безопасность

- **JWT-секрет.** В production (`NODE_ENV=production`) сервер **откажется
  стартовать** без заданного `JWT_SECRET` (≥ 16 символов) — это исключает
  подделку токенов общеизвестным ключом по умолчанию. Установщик генерирует
  секрет автоматически.
- **Секреты не в гите.** `packages\server\.env` и `packages\client\config.json`
  в `.gitignore`. В `config.json` секретов нет — только адрес сервера.
- **CORS.** По умолчанию список источников совпадает с прежним поведением. При
  `CORS_ORIGINS=*` режим `credentials` принудительно отключается (нельзя
  одновременно разрешать любой источник и credentials — это уязвимость).
- **HTTPS.** Для доступа через интернет поднимите сервер за reverse-proxy
  (IIS/nginx/Caddy) с TLS и укажите клиенту `https://` + домен. Клиент
  поддерживает произвольный протокол/порт.
- **Доступ к `.env`.** Ограничьте через NTFS-ACL; не публикуйте файл.
- **Firewall.** Откройте только нужный порт сервера.

## Переменные окружения сервера

| Переменная       | По умолчанию                                   | Описание                                  |
|------------------|------------------------------------------------|-------------------------------------------|
| `PORT`           | `3002`                                         | Порт, который слушает сервер              |
| `HOST`           | `0.0.0.0`                                       | Интерфейс привязки                        |
| `JWT_SECRET`     | — (обязателен в production)                     | Секрет подписи JWT                        |
| `CORS_ORIGINS`   | `http://localhost:8080,http://localhost:3000`  | Список разрешённых источников или `*`     |
| `NODE_ENV`       | `development`                                   | `production` включает строгие проверки    |
| `MAX_BODY_BYTES` | `524288000` (500 MB)                            | Лимит размера тела запроса/ответа         |

См. также `packages\server\.env.example`. Сгенерировать секрет вручную:
`bun run packages\server\scripts\gen-secret.ts`.
