# SuperApp — развёртывание на сервере (deployment)

Этот каталог содержит инструментарий для установки **сервера** и **клиента**
SuperApp не на `localhost`, а на отдельной машине/сервере, с интерактивной
настройкой конфигурации и генерацией секретов.

## TL;DR

```bash
# На сервере (Linux):
./installer/install-server.sh

# На сервере (Windows, PowerShell):
./installer/install-server.ps1

# На машине клиента (Linux/dev):
./installer/install-client.sh

# На машине клиента (Windows, PowerShell):
./installer/install-client.ps1
```

Установщики интерактивно спрашивают параметры (порт сервера, IP/порт сервера для
клиента и т. д.), генерируют секреты и пишут конфигурационные файлы. При
повторном запуске («обновление») можно нажимать Enter — будут подставлены
текущие/значения по умолчанию.

---

## Что делает установщик сервера (`install-server`)

1. Проверяет наличие [Bun](https://bun.sh) (рантайм сервера) и ставит зависимости.
2. Запускает интерактивный конфигуратор `configure-server.mjs`, который:
   - спрашивает **порт** (`PORT`, по умолчанию `3002`);
   - спрашивает **адрес привязки** (`HOST`, по умолчанию `0.0.0.0` — слушать все интерфейсы);
   - спрашивает **разрешённые CORS-источники** (`CORS_ORIGINS`, опционально — для веб-клиента);
   - **генерирует криптостойкий `JWT_SECRET`** (если его ещё нет), используя `crypto.randomBytes`;
   - выставляет `NODE_ENV=production`;
   - пишет всё в `packages/server/.env` с правами `600` (только владелец).
3. Печатает следующие шаги (запуск, настройка systemd/службы Windows, reverse-proxy).

`.env` **не коммитится** (он в `.gitignore`).

## Что делает установщик клиента (`install-client`)

1. Запускает интерактивный конфигуратор `configure-client.mjs`, который спрашивает:
   - **протокол** (`http`/`https`, по умолчанию `http`);
   - **IP/host сервера** (по умолчанию `localhost`);
   - **порт сервера** (по умолчанию `3002`);
   и пишет `packages/client/config.json` (`{ apiBaseUrl, serverHost, serverPort, protocol }`).
2. Собирает клиент (`vite build`) и, на Windows, установщик Electron (`electron-builder`, NSIS).

Десктоп-клиент (Electron) при старте читает `config.json` и направляет все
запросы на указанный сервер вместо `http://localhost:3002`. Порядок поиска
конфигурации (главный процесс Electron):

1. переменная окружения `SUPERAPP_API_URL` (или `SUPERAPP_CONFIG` — путь к json);
2. `config.json` рядом с исполняемым файлом (куда его кладёт инсталлятор);
3. `config.json` в каталоге пользовательских данных приложения (`userData`);
4. `config.json` в корне пакета клиента (для разработки).

## Безопасность

- **JWT-секрет.** В production сервер **откажется стартовать** без заданного
  `JWT_SECRET` (длиной ≥ 16 символов) — это исключает подделку токенов общеизвестным
  ключом по умолчанию. Установщик генерирует случайный секрет автоматически.
- **Секреты не в гите.** `packages/server/.env` и `packages/client/config.json`
  добавлены в `.gitignore`. В `config.json` клиента секретов нет (только URL сервера).
- **CORS.** По умолчанию список источников совпадает с прежним поведением. Если
  задать `CORS_ORIGINS=*`, режим `credentials` автоматически отключается (нельзя
  одновременно разрешать любой источник и куки/credentials — это уязвимость).
- **HTTPS.** Для доступа через интернет рекомендуется поднять сервер за
  reverse-proxy (nginx/Caddy/IIS) с TLS и указать клиенту `https://` + домен.
  Клиент поддерживает произвольный протокол/порт.
- **Права на файлы.** `.env` пишется с правами `600` (на Unix). На Windows
  ограничьте доступ через NTFS-ACL.
- **Firewall.** Откройте только нужный порт сервера; внутренние порты не публикуйте.

## Переменные окружения сервера

| Переменная       | По умолчанию                                   | Описание                                  |
|------------------|------------------------------------------------|-------------------------------------------|
| `PORT`           | `3002`                                         | Порт, который слушает сервер              |
| `HOST`           | `0.0.0.0`                                       | Интерфейс привязки                        |
| `JWT_SECRET`     | — (обязателен в production)                     | Секрет подписи JWT                        |
| `CORS_ORIGINS`   | `http://localhost:8080,http://localhost:3000`  | Список разрешённых источников или `*`     |
| `NODE_ENV`       | `development`                                   | `production` включает строгие проверки    |
| `MAX_BODY_BYTES` | `524288000` (500 MB)                            | Лимит размера тела запроса/ответа         |

См. также `packages/server/.env.example`.
